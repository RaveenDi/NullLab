7. What we could not test

  • We re-ran the evaluation code in the case folder, not the authors' original pipeline, raw data or software versions. Port notes: Python port (sklearn 1.9.1): per-class down-sampled bagged trees (30 peace, 90 war per tree, with replacement, 300 trees vs 1000), mtry grid (2,46,90) tuned by 10-fold stratified CV ROC-AUC (caret default grid for 90 predictors); PR-AUC = sklearn average_precision_score (the reanalysis used aucPRp from Cranmer & Desmarais; small definitional differences).
  • Only two evaluation steps (factors A and B) were varied per run. Other leakage types were not examined, and the model, metric and features are held fixed by construction.
  • Intervals come from an unpaired bootstrap over test rows for 3 seeds (42/43/44). They do not cover variation across training sets, model initialisations or a fresh draw of the data.
  • The excerpt states a forecasting use, but the control used here is not a time-ordered hold-out; a temporal control may give a different size of inflation.
  • Not tested: Kapoor & Narayanan (2023), Leakage and the reproducibility crisis in ML-based science, Patterns 4(9):100804, arXiv:2207.07048, Table A1: train+test imputed together with rfImpute (outcome used); RF AUC reported 0.94 (reproduced 0.95), corrected 0.64. Not built: their raw pre-imputation data is only in CodeOcean capsule doi:10.24433/CO.4899453.v1, which returned HTTP 403 to automated download on 2026-11-01.
  • Contamination: the model that proposed the fix recognised the source of this case in the memorisation probe (excerpt_only, full_agent_view), so its choice of what to fix may be recalled rather than discovered. The measured numbers come from the sandbox, not from the model.

9. Suggested note to the authors

The headline result (0.91) appears to depend on the evaluation protocol: the model is scored on rows it was fit on.

In our reanalysis the code was run with only split_rows, tune_mtry changed (fidelity guard: only step(s) split_rows, tune_mtry changed (split/split)). The same model then scored 0.154 against 0.384 under the claimed protocol (metric: PR-AUC), a drop of +0.231 (mean of seeds 42/43/44; 95% unpaired-bootstrap intervals for the drop: seed 42 [+0.137, +0.398]; seed 43 [-0.114, +0.272]; seed 44 [+0.190, +0.385]; 7140 rows scored by the claim, 1428 after the change).

This matches the leakage pattern 'No test set' (L1.1, Kapoor and Narayanan 2023). We would ask the authors to report the score under an evaluation on rows the model was not fit on (a held-out test set), or to explain why the current protocol is appropriate for the stated use.

We did not re-run the authors' original pipeline and cannot rule out that other choices explain part of the gap.
