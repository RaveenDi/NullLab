# Execution and privacy boundary

This build executes trusted local Python, with Python-level restrictions and OS resource limits. It is not designed to host arbitrary hostile code. The local server rejects non-loopback clients/hosts and cross-origin mutating requests, accepts only enumerated cases or data-only CSV intake, and disables web inference unless explicitly enabled.

Workers preload required libraries, install the restriction before loading case code, scrub credentials from the environment, block network/process creation, and allow writes only in a disposable workspace. Python dependencies are readable but read-only. Remove/mkdir/truncate/chmod-style mutations outside the workspace are refused. A fresh copy of the DataFrame is passed to each experiment/configuration. Native extensions, shared process/module state inside one worker and side channels remain limitations. A new container boundary is required before general public code uploads.

Windows Job Object assignment now fails closed instead of continuing without limits. Subprocesses have time and memory/process constraints. POSIX behavior and Docker factorial execution have not been verified on this workstation. The existing historical Docker path does not certify v2 isolation.

The v2 model prompt contains code, claim text, study declarations, column roles, intended use and aggregate dataset/preprocessing diagnostics. The engine does not sample CSV rows into prompts. Complete source, claim text and declarations can themselves contain confidential data or embedded records: inspect `--preview` and your files. Meta Contributor mode allows training on submitted content; Standard's training policy does not imply zero retention. See current provider terms. The default standard Spark planner and optional Wonder critic are hosted; local compatible inference keeps the transport local when correctly configured.

Credentials come only from explicit environment/.env configuration. They are not logged in provider state. Failed attempts retain reserved estimates; a local timeout cannot establish remote cancellation or exact billing. Budget locks cover a job workspace, not unrelated jobs/accounts. Keep keys and private results out of version control. User-generated cases are gitignored.

Evidence hashes detect byte changes; they are not signatures proving authenticity. Exports fail on missing/mismatched identity and credential-looking text. They contain executable code and potentially private data; inspect before sharing. Prompt injection remains a threat: typed edits and guards limit actions but do not prove immunity. No browser walkthrough was performed, per owner instruction.

Generated CSV studies enforce their entire trusted template by normalized AST comparison, not just a predictor-list constant. Customized code that still claims the generated adapter is rejected; an explicit custom adapter warns that declared roles are unverified. Study answers do not prove availability, independence or appropriate exclusions. Unknown facts and unsupported generated designs stop before fitting/model calls. Saved intake diagnostics are displayed only while their recorded data hash and predictor metadata match; an audit recomputes diagnostics. Revisions create new cases and record parent hashes. Linked audit identity is checked before attaching it. Neither the history nor comparison endpoint upgrades old evidence.

Assessment ZIPs for unmeasured outcomes include raw input data and source, with explicit no-counterfactual language. Both export paths include only manifest-bound inputs, not arbitrary adjacent files. Local job history and study metadata remain private workstation content unless the owner chooses to share them.
