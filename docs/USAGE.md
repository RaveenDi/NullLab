# Research Workdesk workflow

For a guided test with exact files, field values and expected behavior, use the [full product test checklist](TESTING-WORKDESK.md) and [synthetic test kit](../test-materials/workdesk/README.md).

Start the localhost service using the README, open http://127.0.0.1:8099 and choose **Go to Workdesk**. The landing explains the method and scope; **Evidence Lab** contains the recorded worked example and saved audits; **Architecture** explains the actual handoffs. New research starts at `/workdesk`.

1. **Ask your question.** Enter what you want to investigate. Attach a CSV, optionally a compatible Python pipeline and UTF-8 text/Markdown notes. Choose **Start investigation**. Starting, uploading and preparing a plan do not call a model or train a classifier.
2. **Inspect your materials.** NullLab shows observed row/column counts and possible binary targets. Open a material to read its preserved bytes and SHA-256. A file preview never executes code. These observations do not establish valid predictor timing or a suitable study population.
3. **Clarify the study.** Use the research thread for questions. The default **Local study guide** gives deterministic framing guidance. Optional Meta guidance requires reviewing and acknowledging the exact outbound context. It has a separate four-attempt/$0.25 reserved-estimate limit per investigation; it does not itself start an experiment.
4. **Review the Study brief.** Confirm the outcome column, intended decision, population, prediction time, availability and column roles. Choose a generated baseline or your supplied compatible Python. Entity/time fields are metadata; exclude post-decision inputs. Supplied code requires an explicit acknowledgement that you reviewed and trust it for local execution. Declarations are not independently verified facts.
5. **Save brief & prepare plan.** Inspect the six-step plan and revision identity. Changed materials or brief answers invalidate the old plan. Earlier runs stay bound to their original inputs.
6. **Review & run.** The default **Rules & local execution · no key** runs real classifier code with bounded rule-based controls. Optional Meta planning/critique needs explicit outbound acknowledgement for that reviewed plan. Audit jobs reserve at most four attempts/$1 each by default. Estimates are not final provider billing, and unrelated jobs share no account-wide budget guarantee.
7. **Follow Results.** Intake, baseline, hypothesis, guard and measurement show actual checkpoints. Running checkpoints do not display a final scientific conclusion. Inspect per-seed uncertainty, recorded reviews, the tested plan and input identity. A generated baseline with no supported intervention may correctly finish **NOT TESTED**.
8. **Keep and continue the evidence.** Download a measured Evidence ZIP or an explicitly unmeasured assessment ZIP when available. Reload or reopen the investigation from the project rail; its question, thread, materials, revisions and runs persist. Follow-up guidance uses the latest run, which is explicitly labelled if Results displays an older run. Changes require a new reviewed brief/plan and run.

On desktop, the project rail, research thread and study/evidence area share the workdesk. On phones, **Projects** opens the investigation drawer; **Research**, **Study brief**, **Results** and **Materials** choose the task view. Long forms and results scroll within their area. Escape closes dialogs/drawer and restores focus. There is no fullscreen requirement. The landing's continuous decorative animation and the Architecture animation have pause controls and respect reduced motion.

Unknown decision time, population or availability asks concrete questions before any fitting/model dispatch. A complete unseen-entity or future-record request is unsupported by the generated random-row adapter. Represented-entity baselines remain descriptive. Do not change the declared population merely to pass a gate: supply a separately validated pipeline when the real question needs group/time evaluation.

Recorded reviews show actual deterministic checks and model contributions. They do not simulate conversation or vote on scientific truth. Baseline-only outcomes show seed scores without implying a controlled effect. Workdesk URLs preserve `?project=UUID&run=UUID&view=results`. The Evidence Lab's **Return to the evidence** opens saved engine audits at `/evidence?job=UUID`; legacy `/?job=UUID` links resolve there too. Viewing a recording creates no investigation, execution or model call.

Use **Try an example** only when you want a separate investigation copied from bundled public inputs. Review the import dialog; merely following an example link does not import, execute or call a model. For your own study, attach new material or revise the brief and save a new plan. Original material bytes and run inputs remain immutable. Custom Python is not silently regenerated. The retained case/version and descriptive comparison APIs do not compute a causal ranking or a new statistical test.

For an existing trusted Python pipeline, the case folder contains `train.py`, `data.csv`, `excerpt.md`, optionally `case.json`/`contract.json`. A supplied `expected_score` and `score_tolerance` in case.json are checked before planning; mismatch stops attribution. Without a numerical reference, the baseline is an execution of supplied code, not verification of a published number. Required functions are `load(path)`, `feats(df)`, and `claimed_eval(df, seed)` returning one-dimensional equal-length true labels and predictions. AUC metrics require both classes as 0/1. The current instrument accepts at least 20 rows with five per class and a CSV up to 50 MB. Arbitrary project/notebook conversion is not automatic.

```powershell
python -m agent.engine CASE --out out/audit
python -m agent.engine CASE --preview
python -m agent.engine CASE --live --critic --out out/live-audit
python -m agent.intake DATA.csv --target defect --intended-use "Screen independent parts" --decision-time "Before final acceptance" --population independent_records --availability confirmed --entity-column part_id --exclude post_test_status --out examples/my-case
python -m agent.ci_check examples/secom --threshold 0.05
```

The CSV adapter accepts 30–20,000 rows, numeric selected predictors, a binary 0/1 target and a 5 MB file. Text metadata is allowed. At least five records per class and one predictor are required. It creates a new fixed Random Forest baseline with constant zero replacement of missing predictors, not a reproduction of a user's original model. Review whether zero is appropriate. Omitting the brief fields saves an unresolved case that will ask questions. The example CLI metadata/exclusion names must exist in your CSV. Generated-source AST matching enforces the complete template; edited code must use an explicit custom adapter with unverified roles.

No matching rule -> NOT TESTED. A model that proposes no flaw -> MODEL NO FLAW, without empirical clearance. Missing predictor timing or intended population can produce NEEDS INFORMATION with concrete questions. A known concern outside the edit list produces UNSUPPORTED with scope gaps. A consistent positive tested effect -> INFLATED. Mixed or failed measurements -> INCONCLUSIVE. Reviewer objection -> DISPUTED; unresolved objections survive an early no-flaw answer. A consistent score increase is CONTROL SCORE HIGHER, not no effect. No-effect results apply only to the tested controls.

Every job writes `result.json` and immutable input snapshots. `agent.engine.export_bundle(path_to_result)` creates a ZIP for measured v2 results, verifying input/control identity and refusing credential-like text. The ZIP includes inputs, controls, patch, dependency versions and result. Inspect executable code before reproducing. The patch replaces the original file with the normalized compiled control; it is not a formatting-preserving small edit. The result records conditional intervals, not universal statistical coverage.

`agent.engine.export_assessment(path_to_result)` creates a separate assessment ZIP for terminal unmeasured outcomes with verified snapshots, including gated and baseline-only runs. It includes a readable assessment, exact inputs, result and dependency versions. It states that no counterfactual was measured. Both ZIP types contain data and executable source; review before sharing. Extra untracked files beside the snapshot are excluded. A failed run without an input identity cannot export an assessment.

CI returns 1 for a measured effect above threshold, 2 for failure or unchecked/disputed coverage, and 0 for completed checks below threshold. `--allow-unchecked` selects report-only coverage behavior. Legacy `agent.audit` is a historical report reader; historical results without an audit-time manifest cannot be exported as new evidence.
